# 의사결정 그릴

## 준비

현재 구조를 근거로 작성된 living spec 초안과 관련 코드를 읽는다. 사용자 입력에서 시작하는 Use Case, 예외 흐름, 상태와 데이터 소유권, 공개 계약, 비용, 오류, 로그, 보안과 구성요소 책임 중 결과에 영향을 주는 빈칸을 찾는다.

설치돼 있으면 `grill-with-docs`를 인터뷰에, `domain-modeling`을 여러 작업에서 공유할 용어나 ADR 후보 정리에 활용할 수 있다. 두 skill이 설치되지 않아도 이 검토를 계속한다.

## 질문 루프

1. 현재 결정이나 설계의 가정을 구체적인 정상 또는 예외 상황으로 검증한다.
2. 사용자 선택에 따라 제품 행위, 공개 계약, 범위나 책임이 달라지는 빈칸을 질문한다.
3. 선택이 필요하면 상호 배타적인 선택지, 트레이드오프, 추천안과 이유를 제시한다.
4. 답변에 따라 같은 living spec의 결정 상태와 영향을 갱신한다.
5. 새 빈칸이 드러나면 중요도와 현재 범위를 보고 반복 여부를 판단한다.

질문 개수와 순서는 고정하지 않는다. 답을 지금 알 수 없는 항목은 `검토 중`, 방향만 정한 항목은 `잠정 결정`, 현재 구현 기준은 `확정`, 현재 범위를 막지 않는 항목은 `후순위`로 남길 수 있다.

## 기록 위치

결정 배경, 이유와 API·구현·Task 계획에 미치는 영향은 living spec에 둔다. 단순 작업 메모를 ADR로 만들지 않는다.

## spec 작성

검토 결과를 반영한 문서를 제시할 때 `author-reviewable-text`에 산출물 종류, 확인된 사실, 필수 형식과 해당되는 길이 제한을 전달한다. 반환된 living spec을 사용자에게 제시하고 현재 기준본으로 충분한지 리뷰와 승인을 받는다. 미결정 사항이 현재 범위를 막지 않으면 상태를 명시한 채 남길 수 있다.
