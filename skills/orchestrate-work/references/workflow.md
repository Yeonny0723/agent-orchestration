# Living spec 검토 질문

이 문서는 설계의 가정을 검토할 질문을 제공한다. 진행 순서는 [orchestrate-work](../SKILL.md), 산출물의 내용·표기·완료 기준은 [Spec 템플릿](../../../templates/spec.md)을 따른다. 질문을 고정 개수로 모두 묻기보다 현재 작업의 결과를 바꾸는 빈칸에 사용한다.

## 목표와 사용자 행동

- 사용자가 얻으려는 결과와 성공을 확인할 행동은 무엇인가?
- 사용자 입력이나 화면 행동에서 시작하는 흐름 중 빠진 것은 없는가?
- 해당 흐름의 가치가 추가되는 복잡도와 운영 부담을 정당화하는가?
- 구현을 시작하기 전에 줄일 수 있는 범위는 무엇인가?

## 구조와 상태

- 현재 코드의 어떤 근거가 이 설계를 가능하게 하거나 제한하는가?
- 상태가 충돌하거나 결과가 늦게 도착할 때 어떤 주체의 판단을 따르는가?
- 저장 필드나 새 엔티티를 없애면 어떤 사용자 행동·운영 정책을 지원할 수 없게 되는가?
- 책임을 옮기거나 기존 구조를 재사용하면 중복과 복잡도가 줄어드는가?

## 예외와 운영

- 부분 실패 뒤 사용자가 다시 접근하면 무엇을 보고 어떤 행동을 할 수 있는가?
- 사용자에게 보이는 종료와 실제 자원 정리 사이에 시간 차이가 있는가?
- 비용·성능·보안·개인정보·호환성 제약이 사용자 흐름을 바꾸는가?
- 복구를 맡는 주체에게 필요한 상태·로그·권한이 있는가?

## 결정과 실행 가능성

- 답을 모르는 항목이 현재 착수나 출시를 실제로 막는가?
- 외부 담당자의 준비 없이 지금 입증할 수 있는 사용자 가치는 무엇인가?
- 목업에서 통과한 검증 중 실제 시스템 연결 후 다시 확인해야 하는 것은 무엇인가?
- 결정 변경이 연결된 계약·그림·Task에 빠짐없이 반영됐는가?
