# 전체 워크플로우

## 규모 판정

`work-scale.md`의 독립 산출물 기준으로 소형, 중형, 대형을 정하고 근거를 한 문장으로 남긴다.

## 범위 탐색

`superpowers:brainstorming`으로 문제, 목적, 현재 구조, 제약, 비목표와 완료 기준을 탐색한다. 중형과 대형은 spec에 영향을 주는 결정을 전수 목록화한다.

## 의사결정

`decision-first-grill`로 목록의 결정을 한 번에 하나씩 확정한다. 소형은 모호할 때만 최대 두 질문을 사용한다.

## spec 승인

결정이 모두 확정된 뒤 spec을 작성하고 사용자 리뷰를 받는다. spec 승인 없이는 plan으로 진행하지 않는다.

## 계획 기술 합의

plan 작성 중 구현 수준에서 공동 합의가 필요한 선택만 하나씩 묻는다. 단순 내부 세부사항은 agent가 정한다. spec 계약을 바꿔야 하면 spec 수정과 사용자 리뷰로 돌아간다. plan 자체는 기본 사용자 리뷰 게이트가 아니다.

## TDD 기반 구현

`implement-with-tdd`에 위임한다. 사용자가 이 skill만 직접 호출할 수도 있다. 완료 근거는 실제 변경 범위와 일반 검증 명령 및 결과다.

## 테스트 민감도

`verify-test-sensitivity`에 위임해 변경 행위를 깨는 작은 mutation을 관련 테스트가 잡는지 확인한다. mutation 복원과 원본 상태 재검증이 종료 조건이다.

## 선택형 작업 이해

사용자가 `understand-work`를 명시적으로 호출할 때만 실행한다. 질문, 답변과 피드백은 현재 대화에만 두며 호출하지 않거나 답변이 부족해도 PR을 포함한 다른 절차를 차단하지 않는다.

## PR 작성

사용자가 원하는 코딩 에이전트 세션에서 `write-pr`를 명시적으로 호출한다. 해당 agent는 별도 중간 문서 없이 승인된 spec, 실제 diff와 현재 검증 근거를 직접 읽는다.
