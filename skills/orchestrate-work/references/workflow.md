# Living spec 검토 관점

이 문서는 고정 단계가 아니라 초기 spec을 비판적으로 검토할 때 참고할 관점이다. 현재 작업에 관련된 항목만 사용한다.

## 기능과 입력 경계

- 사용자가 달성하려는 결과와 선언된 입력 경계는 무엇인가?
- 정상, 빈 입력, 잘못된 입력, 중복, 취소와 재시도는 어떻게 보이는가?
- 각 Use Case는 MVP 포함, 후순위 또는 제외 중 어디에 속하는가?

## 상태와 데이터 흐름

- 상태를 누가 만들고 보관하며 폐기하는가?
- 구성요소 사이에서 전달되는 필드와 응답 형태는 무엇인가?
- 부분 성공이나 오래된 상태를 어떻게 다루는가?

## 운영 경계

- 응답 크기, 비용, 지연과 자원 제한은 어디에서 통제하는가?
- 오류를 누구에게 어떤 형태로 전달하며 재시도와 복구 책임은 어디에 있는가?
- 요청, 대화와 비용을 구분하기 위한 로그 식별자는 무엇인가?

## 결정 정합성

결정이 바뀌면 같은 living spec의 계약, Task 체크리스트와 관련 구현을 함께 갱신한다. 아직 답을 알 수 없는 항목은 상태와 현재 작업에 미치는 영향을 기록한다.
