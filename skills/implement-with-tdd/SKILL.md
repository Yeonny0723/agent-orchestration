# TDD 기반 구현

이 skill은 사용자 직접 호출 또는 `execute-task`가 선택한 구현 전략으로 실행한다.

## 진입 조건

1. 현재 Task의 목표, 관찰 가능한 완료 조건과 관련 저장소 지침을 확인한다.
2. 필요한 spec이나 plan이 있다면 현재 Task와 관련된 결정만 확인한다.
3. 적용할 convention pack과 기존 테스트 방식을 확인한다.
4. 구현 결과를 바꾸는 필수 정보가 없으면 해당 결정만 질문하거나 living spec에 반영한다.

모든 spec 결정을 확정하거나 별도 plan을 만드는 것은 진입 조건이 아니다.

## 실행

설치돼 있으면 `superpowers:test-driven-development`의 세부 지침을 사용할 수 있다. 설치되지 않아도 다음 TDD 절차를 계속한다.

1. 한 행위를 설명하는 실패 테스트를 먼저 작성한다.
2. 테스트를 실행해 구현 부재나 실제 결함 때문에 실패하는지 확인한다.
3. 통과에 필요한 최소 구현을 작성한다.
4. 관련 테스트를 통과시킨 뒤 중복, 이름과 구조를 정리한다.
5. 변경 영향 범위에 적절한 일반 검증을 실행한다.
6. 실제 변경, 검증 명령과 결과를 호출자에게 반환한다.

새 테스트의 결함 감지력이 불확실하거나 회귀 위험이 크면 `verify-test-sensitivity`를 선택할 수 있다. 모든 Task의 다음 단계로 요구하지 않는다.

## 책임 경계

Task 분할, spec 전체 검토, 테스트 mutation, 사용자 리뷰, 커밋, 작업 이해 질문과 PR 절차를 복제하지 않는다.
