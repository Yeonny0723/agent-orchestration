# Clean TypeScript 전체 규칙

Robert C. Martin의 Clean Code 17장 규칙을 TypeScript에 맞춰 적용한다.

## 주석 (C1-C5)
- C1: 주석에 메타데이터를 넣지 않는다. 이력은 Git이 관리한다
- C2: 낡은 주석은 즉시 삭제한다
- C3: 코드를 그대로 반복하는 주석을 쓰지 않는다
- C4: 꼭 써야 하는 주석은 제대로 쓴다
- C5: 주석 처리한 코드를 커밋하지 않는다

## 환경 (E1-E2)
- E1: 빌드는 명령 하나로 끝난다 (`npm run build`)
- E2: 테스트는 명령 하나로 끝난다 (`npm test`)

## 함수 (F1-F4)
- F1: 인수는 최대 3개, 그 이상은 parameter object나 interface로 묶는다
- F2: 출력 인수를 쓰지 않고 반환값을 쓴다
- F3: 플래그 인수를 쓰지 않고 함수를 나눈다
- F4: 죽은 함수를 삭제한다

## 일반 (G1-G36)
- G1: 한 파일에 한 언어만 담는다
- G2: 예상되는 동작을 실제로 구현한다
- G3: 경계 조건을 처리한다
- G4: 안전장치를 무시하지 않는다
- G5: DRY, 중복을 남기지 않는다
- G6: 추상화 수준을 일관되게 유지한다
- G7: 기반 클래스가 파생 클래스를 알지 못하게 한다
- G8: 공개 인터페이스를 최소로 유지한다
- G9: 죽은 코드를 삭제한다
- G10: 변수를 사용하는 위치 가까이 선언한다
- G11: 일관성을 지킨다
- G12: 불필요한 잔재를 제거한다
- G13: 인위적인 결합을 만들지 않는다
- G14: 다른 클래스의 데이터를 탐내지 않는다 (feature envy)
- G15: 선택자 인수를 쓰지 않는다
- G16: 의도를 흐리지 않는다
- G17: 코드를 있어야 할 자리에 둔다
- G18: 정적 메서드보다 인스턴스 메서드를 택한다
- G19: 설명용 변수를 활용한다
- G20: 함수 이름이 하는 일을 그대로 말하게 한다
- G21: 알고리즘을 이해하고 쓴다
- G22: 논리적 의존성을 물리적으로 드러낸다
- G23: if/else 대신 다형성을 택한다
- G24: 관례를 따른다 (TypeScript 스타일 가이드 + ESLint/Prettier)
- G25: 매직 넘버 대신 이름 붙인 상수를 쓴다
- G26: 정확하게 작성한다
- G27: 관례보다 구조로 강제한다
- G28: 조건문을 캡슐화한다
- G29: 부정 조건을 피한다
- G30: 함수는 한 가지만 한다
- G31: 시간적 결합을 드러낸다
- G32: 임의로 정하지 않는다
- G33: 경계 조건을 캡슐화한다
- G34: 함수 하나에 추상화 수준 하나만 둔다
- G35: 설정은 상위 수준에 둔다
- G36: 디미터 법칙, 연쇄 호출을 만들지 않는다

## TypeScript 전용 (TS1-TS3)
Java 전용 규칙(J1-J3)을 TypeScript 관례로 옮긴 것이다.
- TS1: import를 명시적이고 안정적으로 유지한다. namespace 남용과 암묵적 의존을 피한다
- TS2: 매직 상수 대신 enum이나 리터럴 union 타입을 쓴다
- TS3: 공개 인터페이스에 타입을 명시하고 경계에서 `any`를 쓰지 않는다

## 이름 (N1-N7)
- N1: 서술적인 이름을 고른다
- N2: 추상화 수준에 맞는 이름을 쓴다
- N3: 표준 용어를 쓴다
- N4: 모호하지 않은 이름을 쓴다
- N5: 이름 길이를 유효 범위에 맞춘다
- N6: 인코딩(헝가리안 표기 등)을 붙이지 않는다
- N7: 이름이 부수효과까지 설명하게 한다

## 테스트 (T1-T9)
- T1: 깨질 수 있는 것은 모두 테스트한다
- T2: 커버리지 도구를 쓴다
- T3: 사소해 보여도 건너뛰지 않는다
- T4: 무시된 테스트는 요구사항이 모호하다는 신호다
- T5: 경계 조건을 테스트한다
- T6: 버그가 난 주변을 집중적으로 테스트한다
- T7: 실패 패턴을 살핀다
- T8: 디버깅할 때 커버리지를 확인한다
- T9: 테스트는 빨라야 한다 (개당 100ms 미만)

## 안티패턴 (하지 말 것 → 할 것)

| ❌ 하지 말 것 | ✅ 할 것 |
|----------|-------|
| 모든 줄에 주석 | 자명한 주석 삭제 |
| 한 줄짜리 헬퍼 | 코드에 인라인 |
| 곳곳에 `import * as utils` | named import로 의존을 명시 |
| 공개 API에 `any` | 구체 타입 또는 `unknown` + 좁히기 |
| 매직 넘버 `86400` | `const SECONDS_PER_DAY = 86400` |
| `process(data, true)` | `processVerbose(data)` |
| 깊은 중첩 | 가드 절, early return |
| `obj.a.b.c.value` | `obj.getValue()` |
| 100줄 넘는 함수 | 책임 단위로 분리 |

## 에이전트 행동 규칙

코드를 리뷰할 때는 규칙 번호로 위반을 지목한다 (예: "G5 위반: 로직 중복").
코드를 수정할 때는 무엇을 고쳤는지 규칙 번호와 함께 보고한다 (예: "수정: 매직 넘버를 `SECONDS_PER_DAY`로 추출 (G25)").
